Organization mailboxes

Mailboxes colleagues shared with your organization. Your role on each decides whether you can change its settings and schedule; anyone with access can process it on the Inbox page.

    Organizations

    Connect a Microsoft 365 organization once with its API keys, then add its shared AP / AR mailboxes.

    Add an organization

    An Azure app registration in that tenant with Microsoft Graph application permissions Mail.Read and Mail.Send, admin-consented. Limit it to the AP/AR mailboxes with an Exchange application access policy. The keys are stored encrypted and never shown again.

    Add mailboxes

    Each address is checked before it is added. Type, destination and forwarded categories apply to every mailbox in this batch and can be changed per mailbox afterwards. Find lists the shared mailboxes the person has Full Access to (granted directly, not through a group); it needs the Azure app to have Exchange.ManageAsApp and the Global Reader role.

        My mailboxes

        Mailboxes you connected. Open one to set its type (AP or AR), what is forwarded and where, and whether your organization can use it.

        Mailboxes connected by sign-in keep an encrypted Microsoft token only for the period you choose, then delete it. Reconnect to extend.

        Add a shared mailbox

        You'll sign in with your own Microsoft 365 account, which needs Full Access to this mailbox (and Send As or Send on Behalf to forward emails from it). Ask your Microsoft 365 admin if you don't have it. For many mailboxes, add an organization above instead.

        Shared mailboxes

        Selected mailboxes are read through the account you signed in with, for the same access period. Only mailboxes that account has Full Access to can be added.
